# 收口版归因者题面（**臂 ④-收口** 专用 · 与 `prompt.md` 只差一处判据）

> 逐字使用。与原题面的**唯一差别**：把「改哪一条最可能防止这一天的亏损」（机械读法：把仓位改小）
> 换成「哪一条规则**在当天的事实下被判错了**」（意图读法），并显式排除前者。
> 起因：`challenges.md` C-01 —— 两种读法只在唯一的 `NONE` 天（day-03）上分歧，而那天的答案
> 正是审稿意见点名的「自己出题自己答」。这一枪把判据先写死在题面里。

---

你是一个自进化交易系统的审计员。下面给你两样东西：

1. **规则集**（`RUBRIC.md`）：系统当前生效的"条件 → 动作"规则，以及仓位是怎么算出来的（唯一口径）。
2. **某一天的完整记录**：当天的市场事实、当天逐条触发的规则与读数、算出来的仓位、以及结果。

任务：判断**哪一条规则在当天的事实下被判错了** —— 也就是说，**按当天能看到的事实，这条规则的触发条件或它的动作本来就不该那样生效**。

⚠️ 两条口径，必须分清：

- **不要**回答「改哪条最能让这一天的亏损变小」。**单纯把仓位改小不算判对**：在亏损的那一天，把任何一条规则的仓位乘子调小都会让亏损变小，那不是"判错"。
- 你要判的是**规则在当天的事实下站不站得住**。若判断没有任何规则站不住（亏损来自记录之外），报 `NONE`。

- 只报**一个**规则的编号（R1–R6）。
- 不要复述规则集，不要写分析过程之外的内容。

输出**恰好两行**，写进答案文件：

```
FAULT: <R1|R2|R3|R4|R5|R6|NONE>
WHY: <一句话；必须引用记录里的某个具体数字>
```
